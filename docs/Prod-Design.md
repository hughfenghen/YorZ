# 产品设计

## 目标

- 提高专业程序员的效率
- 降低程序开发的门槛
- 将编程工作真正适配到移动平台

### 理念

- 编程 = 做选择题
- 产品 = 初始创意 + 决策路径的累积

### 路径/手段

- Agent 做信息整理、分析、执行
- 用户做：需求、决策、Review，通过 GUI 降低知识、交互门槛

## Skill

创建一系列通用 skill，使用skill来规范/驱动 Agent的工作流：

1. 用户输入需求或 Bug
2. Agent 分析需求相关联的信息：
   - 项目代码、项目文档、历史需求 spec 文档
   - 保证用户原始目的不变的前提下，完善需求描述，补充需求相关的信息：关联文档路径、关联代码位置
3. Agent 根据需求及关联信息，分析当前现状
4. Agent 根据需求及现状，生成技术方案
   - 存在多种实现方案，对项目影响重大的方案，信息缺失、或需求逻辑不完备、或逻辑冲突存在疑问
   - 需要用户人工审阅
     - 提供决策建议、决策所需的辅助信息
5. 用户审阅方案，进行决策
6. Agent 根据技术方案及用户决策，拆解为任务清单跟测试用例
7. Agent 执行任务清单，生成执行记录
8. 用户 Review Agent 输出结果（执行记录中的重要信息、文档，核心流程、架构、模块代码的图形化表达）

_以上流程，允许用户二次介入（补充新增需求、录入新 bug）重开流程_

> spec 驱动 Agent 开发的 skill 可参考 @docs/ai-spec-drive-skill/SKILL.md

## CLI

**定位：Agent 使用（启动 Service 、安装 skill）该产品的入口**

- cli 支持将 skill安装到用户已安装的Agent 对应的 skills 目录中，或当前项目
- cli 支持运行服务，将Agent输出的内容渲染为 HTML

## Service

**定位：Agent 与 GUI 之间的桥梁、翻译**

- 由 cli 工具启动，提供 HTTP 服务
- 提供用户交互的 GUI ，进行工作流中的：需求编辑/整理辅助、审阅决策辅助、Agent 输出 Review 辅助

## GUI

**目标：大幅降低编程的知识、交互门槛**

- 将 Agent 输出的内容渲染为 HTML
  - 建议通过 skill 让 Agent 输出 json 格式的文档
  - 或带自定义标记的 Markdown 文档，前提是能作为复杂交互的数据源
- 提供需求编辑/整理辅助、审阅决策辅助、Agent 输出 Review 辅助
- 需要丰富的，锲合工作流的，编程常用的，能**实现上述目标**的图形化交互组件，如
  - 流程图，图形化表达函数运行逻辑
  - 数据流图
  - 模块依赖图
  - 软件逻辑架构图
  - 时序图
  - code graph
  - 信息卡片：能展示高度浓缩信息、能展开详细信息、能突出重点信息、能关联调整相关信息
- 良好的移动端交互适配

### 需求编辑/整理辅助

**定位：便捷输入、精确关联，收集用户的输入信息启动 Agent 工作流**

- 支持输入需求/bug文字，上传图片
- 支持提及（@） 项目模块、过往 spec 文档

### 审阅决策辅助

**目标：帮助用户快速理解问题、建立认知模型、评估风险**

- 展示Agent的方案建议，收集用户的选择
- 提供问题与方案总结描述，可展开详细信息
- 提供问题与方案的关联信息（文档、代码、知识），可便捷跳转或让 AI 二次解释
- 复杂信息尽量图形化表达

### Agent 输出 Review 辅助

**目标：概括性展现 Agent 输出结果，帮助用户快速评估质量**

- 背景
  - Review 代码太困难，专业程序员Review都赶不上 AI 的Coding 效率
  - 在移动端设备 Review 代码、Review 大篇幅 md 文档不可行
- 期望
  - 以各种图形、图表、信息卡片来表达 Agent 输出，替代 git diff
    - 基于概括性信息，与 AI 结对Review
  - 支持一键 AI Review

## 项目知识库

项目知识库对建立技术地图、辅助用户决策有非常大帮助，先依赖 Agent 的隐性管理或其他 Agent 插件提供，MVP 版本不做。
