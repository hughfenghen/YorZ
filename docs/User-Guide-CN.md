## 1. 安装

使用 pnpm 安装：

```bash
pnpm add -g @yorz/cli
```

或使用 npm 安装：

```bash
npm install -g @yorz/cli
```

安装后可以运行以下命令确认 CLI 可用：

```bash
yorz --help
```

## 2. 启动服务

在任意目录运行：

```bash
yorz serve
```

`yorz serve` 会启动 YorZ Service，默认在后台运行。服务启动后，在浏览器打开：

```text
http://localhost:7423
```

启动时 YorZ 会检查内置 skills（`yorz-spec` / `yorz-debug` / `yorz-git-ops`）。如果缺失或不是最新版本，会安装或更新到共享目录 `~/.config/yorz/skills/`，所有 YorZ 项目复用同一份。三个 skill 的分工是：`yorz-spec` 驱动 spec 文档的 plan / tasks / execute 状态机，`yorz-debug` 承载「假设 → 取证 → 验证」的疑难调试纪律，`yorz-git-ops` 约束 Review 页的提交、暂存、丢弃等 git 操作。

YorZ 不再向各 Agent 自身的 skills 目录写入，因此这些 skill 不会出现在非 YorZ 会话中——YorZ 改为在 prompt 中传入 `SKILL.md` 的绝对路径，由 Agent 按需读取。旧版本写入 `~/.claude/skills/`、`~/.config/opencode/skills/`、`~/.codex/skills/` 的残留会在每次启动时自动清理（也可手动执行 `yorz uninstall skills --legacy`）。

开发或排查服务问题时，也可以让服务留在前台：

```bash
yorz serve --foreground
```

如默认端口被占用，可以指定端口：

```bash
yorz serve --port 7424
```

若指定端口也被占用，YorZ 会依次尝试其后的 9 个端口。服务只监听回环地址（默认 `127.0.0.1`），不支持对外网暴露。

## 3. 停止与重启服务

停止后台运行的 YorZ Service：

```bash
yorz serve stop
```

如果没有后台服务在运行，命令会直接提示当前未运行；如果存在过期运行时记录，YorZ 会清理对应记录。

重启后台服务（先停止再以后台方式重新拉起）：

```bash
yorz serve restart
```

`yorz serve restart` 会立即返回，真正的停止与拉起动作由一个独立子进程完成。因此即使在服务自身的进程里触发（例如 GUI 中版本更新后点「重启服务」），也能正常完成重启。重启会中断正在运行的 Agent 任务，恢复后可以在 Chat 中发送「继续」让 Agent 接着做。

## 4. 查看服务日志

`yorz serve` 默认在后台长期运行，服务日志会写入全局配置目录下的 `logs/`：

```text
~/.config/yorz/logs/
```

日志目录跟随全局配置目录的解析规则：设置了 `XDG_CONFIG_HOME` 时为 `$XDG_CONFIG_HOME/yorz/logs/`；设置了 `YORZ_HOME` 时优先取 `$YORZ_HOME/logs/`。

目录下有两个文件，分工不同：

| 文件              | 内容                                                                                 | 体积控制                              |
| ----------------- | ------------------------------------------------------------------------------------ | ------------------------------------- |
| `serve.log`       | **主日志**：服务启停、HTTP 路由错误与慢请求、Agent 派发与失败、文件监听、worktree 操作、进程崩溃堆栈 | 单文件上限 5MB，滚动保留 1 份归档     |
| `serve-stdio.log` | 后台子进程 stdout/stderr 的兜底记录（第三方库直接打印、Node 致命错误）                | 每次启动覆盖重写，不会持续增长        |

`serve.log` 写满 5MB 后会被重命名为 `serve.log.1`（覆盖上一份归档），随后新建空的 `serve.log` 继续写入。因此日志目录最多占用约 10MB，不会无限增长。

每行日志格式固定，便于 `grep` 过滤：

```text
[2026-07-28T12:00:00.000Z] [error] [http] route error {"method":"GET","path":"/api/projects","status":500}
```

依次是 ISO 时间戳、日志级别（`debug` / `info` / `warn` / `error`）、来源模块、消息与结构化附加信息。

实时查看：

```bash
tail -f ~/.config/yorz/logs/serve.log
```

排查问题时可以调高日志粒度，重启服务后生效：

```bash
YORZ_LOG_LEVEL=debug yorz serve
```

`YORZ_LOG_LEVEL` 支持 `debug` / `info` / `warn` / `error`，默认为 `info`。`debug` 会额外记录每个 HTTP 请求和 spec 文件变更事件。

> 反馈问题时，请优先附带 `serve.log`；如果服务是启动即退出、或完全没有生成 `serve.log`，再补上 `serve-stdio.log`。日志中只记录 sessionId、prompt 长度、耗时等元信息，不会写入 prompt 正文或 Agent 输出内容。

## 5. 添加项目

首次使用 GUI 前，需要把项目目录注册到 YorZ：

```bash
yorz add /path/to/your/project
```

`yorz add` 会完成这些动作：

- 创建项目级 `.yorz/specs/` 目录。
- 检查目标目录是否是 git 仓库；不是时会交互询问是否执行 `git init`，非交互场景可用 `--yes` 允许 YorZ 自动执行。若既非 git 仓库又未确认，命令会直接失败退出。
- 将 `.yorz/tmp` 加入 `.gitignore`，避免临时运行数据进入版本控制。
- 将项目注册到 YorZ Service 的全局项目列表。

添加后刷新 GUI，左侧项目列表会显示该项目。

## 6. 配置目录说明

YorZ 主要使用项目级目录保存 spec 文档与项目相关配置，使用全局目录保存项目列表、个人偏好和服务运行状态。

### 6.1 项目级 `.yorz/`

项目根目录下的 `.yorz/` 是当前项目的 YorZ 工作目录。

常见内容：

- `.yorz/config.json`：项目配置，包含项目 Agent 覆盖方式（`agent`）、spec 文档目录（`specsDir`）、项目命令（`commands`）和项目级自定义斜杠指令（`customInstructions`）。这份文件建议提交到 git，方便团队成员共享同一套命令与指令。
- `.yorz/specs/`：默认 spec 文档目录。每个 spec 通常位于 `.yorz/specs/<spec-id>/spec.md`。
- `.yorz/specs/<spec-id>/debug.md`：Debug 模式记录文件，仅在对应 spec 进入 Debug 流程后出现。
- `.yorz/tmp/`：运行时临时目录，不应提交到 git（`yorz add` 会自动写入 `.gitignore`）。其中 `commands/` 保存项目命令的运行记录与日志，`sessions/` 保存会话索引，`drafts/` 保存新建 spec 的草稿附件。

如果在 GUI 的「项目配置」里修改 spec 文档目录，新的 spec 会写入新目录；旧 spec 仍留在原目录，需要按提示自行迁移。

### 6.2 全局配置目录

YorZ 的全局配置目录默认位于：

```text
~/.config/yorz
```

如果设置了 `XDG_CONFIG_HOME`，则使用：

```text
$XDG_CONFIG_HOME/yorz
```

如果设置了 `YORZ_HOME`，则优先使用 `YORZ_HOME` 指向的目录。

常见全局文件：

- `config.json`：**当前唯一的全局配置文件**，保存已添加项目列表、全局默认 Agent、会话结束提示、快捷键、防休眠策略、外观偏好（色彩模式 / 主题 / 语言）和全局自定义斜杠指令。
- `projects.json`：旧版本遗留的项目列表文件。仅在 `config.json` 不存在时被兼容读取一次，之后所有写入都只落到 `config.json`。
- `runtime.json`：后台 Service 的运行记录。
- `skills/`：共享的内置 skills 目录，包含 `yorz-spec/`、`yorz-debug/`、`yorz-git-ops/`。
- `logs/`：服务日志目录，包含 `serve.log`（滚动主日志）与 `serve-stdio.log`，详见 [4. 查看服务日志](#4-查看服务日志)。

个人偏好（外观、主题、语言、快捷键、自定义指令等）现在统一存放在用户级 `config.json`，因此换一个浏览器或换一个项目也能保持一致。旧版本存在浏览器 localStorage 里的主题与语言会在首次加载时自动迁移过来。

通常不需要手工编辑全局配置目录；优先通过 `yorz add`、GUI 项目列表、GUI 全局配置和 `yorz serve stop` / `yorz serve restart` 管理。

### 6.3 环境变量

| 变量                     | 作用                                                                 | 默认值            |
| ------------------------ | -------------------------------------------------------------------- | ----------------- |
| `YORZ_HOME`              | 全局配置目录，优先级最高                                             | 未设置            |
| `XDG_CONFIG_HOME`        | 次优先，实际使用 `$XDG_CONFIG_HOME/yorz`                             | `~/.config/yorz`  |
| `YORZ_LOG_LEVEL`         | 日志级别：`debug` / `info` / `warn` / `error`                        | `info`            |
| `YORZ_WATCH_USE_POLLING` | 设为 `1` 时文件监听改用轮询模式，适用于网络盘、容器等场景            | 未启用            |
| `YORZ_AGENT_CMD`         | 覆盖 Agent 启动命令，优先级高于项目配置，一般仅用于测试与特殊接入场景 | 未设置            |

## 7. GUI 功能介绍

### 7.1 界面布局

GUI 采用三栏结构：

1. **左侧项目列表**：切换项目、打开项目配置。
2. **中间 Chat 面板**：常驻的对话区，无论当前打开哪个页面都可见，切换页面不会中断对话。面板顶部标题栏右侧可以「折叠 Chat」/「展开 Chat」；折叠后只剩一条竖边。面板右边缘可以拖拽调整宽度，宽度与折叠状态都会被记住。
3. **右侧主区域**：spec 列表、spec 详情、Review、Debug、命令详情等页面。

主区域的 spec 相关页面右上角有「全屏」按钮（默认快捷键 `Ctrl+Shift+F`），进入后会临时折叠项目列表与 Chat 面板，专注阅读文档；按 `Esc` 或再次点击即可退出。在 spec 列表、详情、Review、Debug 之间来回跳转不会丢失全屏状态，退出全屏后你原本手动折叠的侧栏设置也会被保留。

### 7.2 外观与语言

GUI header 最右侧有三横配置入口，点击后可以：

- `切换语言`：中文 / English。
- `外观`：包含「色彩模式」与「主题」两组。
- `全局配置`：打开全局配置弹窗，详见 [7.3](#73-全局配置)。

**色彩模式**有三个选项：

- `跟随系统`（默认）：随系统亮暗设置实时切换。
- `亮色`
- `暗色`

**主题**有三套，可与任意色彩模式自由组合：

- `终端`（默认）：等宽终端风格配色。
- `石墨`：低饱和中性灰阶，信息密度高、视觉噪音低。
- `纸感`：暖白纸底配墨黑正文，适合长时间阅读 spec 文档。

外观与语言保存在用户级 `config.json`，跨项目、跨浏览器生效。

### 7.3 全局配置

在 header 三横菜单中点击「全局配置」打开弹窗。弹窗**没有保存按钮，每一项改动都会立即自动保存**，标题右侧会依次显示「保存中…」和「已保存」。

全局配置包含四组：

- `默认 Agent`：选择 ClaudeCode、OpenCode 或 Codex。未设置项目级覆盖的项目会继承这个默认值，初始值为 ClaudeCode。
- `会话结束提示`：可分别开启「横幅提示」和「声音提示」。两个开关默认关闭，开启后由 YorZ Service 在 Agent 轮次结束时以 best-effort 方式调用系统通知或声音能力；如果当前系统不支持，对会话结束流程没有影响。
- `任务运行期间防休眠`：三选一，默认「系统默认」。选择「禁止息屏」可在有 Agent 会话运行时阻止屏幕熄灭；选择「禁止休眠」则进一步阻止系统进入睡眠。仅在**存在运行中的会话**时生效，会话全部结束后立即释放。macOS、Linux、Windows 均已支持；若当前系统缺少对应能力，会自动回落到「系统默认」，不影响任务执行。
- `快捷键`：详见 [7.4](#74-快捷键)。

### 7.4 快捷键

在全局配置弹窗的「快捷键」区块可以自定义三个动作的键位：

| 动作         | 默认键位       | 说明                                                 |
| ------------ | -------------- | ---------------------------------------------------- |
| `新建 spec`  | `Ctrl+Shift+N` | 打开新建 spec 页；已在该页时新开一个                 |
| `页面最大化` | `Ctrl+Shift+F` | 在 spec 列表 / 详情 / Review / Debug 页切换全屏      |
| `项目设置`   | `Ctrl+Shift+S` | 打开或关闭当前项目的项目配置弹窗                     |

修改方式：

1. 点击该行右侧的「录制」按钮，按钮变为「录制中」，键位处提示「按下新的组合键…」。
2. 直接按下想要的组合键，即刻生效并自动保存。
3. 录制过程中按 `Esc` 取消本次录制；按 `Backspace` / `Delete` 清除该项绑定。
4. 点击「重置」把该动作恢复为默认键位（已是默认时按钮为禁用态）。

如果三个动作的键位重复，冲突项会标红并提示「快捷键不能重复绑定」，此时不会保存。注意默认键位在 macOS 上同样使用 `Ctrl` 而非 `Command`。「页面最大化」与「项目设置」属于开关型动作，即使焦点在输入框内也能触发；「新建 spec」在输入文本时不会被误触发。

快捷键配置保存在用户级 `config.json`。

### 7.5 项目配置 Agent 方法

在 GUI 左侧项目列表中，点击项目旁的配置入口（或按 `Ctrl+Shift+S`），打开「项目配置」。

可以配置：

- `Agent`：默认选择「继承全局默认」，也可以显式选择 ClaudeCode、OpenCode、Codex 或自定义命令。
- `命令 (cmd)` 与 `参数 (args，空格分隔)`：仅在选择「自定义」时填写。
- `spec 文档目录`：相对项目根路径，默认是 `.yorz/specs`。

保存后，该项目后续新建 spec、续跑 spec、追加任务、Chat 对话和 Review 会使用解析后的 Agent：项目选择「继承全局默认」时使用全局默认 Agent，项目选择具体 Agent 或自定义命令时优先使用项目配置。

### 7.6 Chat 对话

Chat 面板是常驻的对话区，适合处理不必开 spec 的零散任务：问代码、改个小 bug、跑一段分析，也可以从这里直接进入 spec 或 debug 流程。

**会话列表**位于 Chat 面板顶部：

- 标题显示「会话（N）」，N 是当前执行中的会话数量；点击标题或右侧箭头可折叠列表。
- 右侧的 `3行 / 5行 / 10行` 用于调整列表可视高度，超出部分内部滚动。
- 每一行显示 Agent 类型标签、会话标题和相对时间（如「5 分钟前」），鼠标悬停可看精确时间；执行中的会话带有旋转图标；有新活动的会话会自动上浮。
- 点击任意一行即可切换到该会话。列表会合并 YorZ 自身的会话索引与 Agent CLI 的原生会话，因此你在 YorZ 之外用 claude / codex / opencode 开过的会话也能在这里找到并继续。

**发送消息**：

- 输入框支持 `Enter` 发送、`Shift+Enter` 换行；使用输入法时的确认回车不会误发。
- 输入 `@` 可以模糊搜索并引用项目内文件；在行首输入 `/` 会弹出指令候选，详见 [7.7](#77-自定义斜杠指令)。
- 回形针按钮可以「导入附件」，最多 10 个、单个不超过 5MB，支持图片、PDF、txt、md；图片也可以直接用 Cmd/Ctrl-V 粘贴。
- 会话运行期间，发送按钮会变为「中止」，可随时打断当前轮次。
- 输入框下方的 `+`「新建会话」会把面板切回草稿态，真正的会话在第一次发送时才创建，因此不会产生空壳会话。

**阅读体验**：

- 消息按「用户发言」分组：两次用户发言之间的所有 Agent 输出与工具调用会合并进同一个气泡，不再一条消息一个气泡。
- 工具调用默认折叠成 `[工具] ×N` 一行，点开可查看名称、入参和结果。
- Agent 回复中的 `文件路径:行号` 可点击复制路径。
- 刷新页面后会从 Agent 的会话记录还原历史，渲染结果与实时看到的一致。

**剩余用量提示**：当 Chat 处于新建的空会话状态时，提示语下方会显示当前 Agent 的模型剩余用量，例如「claude 用量：5-hour 剩余约 62%（已用 38%，重置：…）」。切换到已有会话后该行消失。不同 Agent 的支持程度不同：ClaudeCode 与 Codex 可直接查询；OpenCode 需要先安装 `opencode-quota` 插件，界面会给出对应的安装命令。查询失败只会降级显示提示文案，不影响正常发送消息。

### 7.7 自定义斜杠指令

自定义斜杠指令用于把常用的提示词沉淀成一条 `/指令`，例如 `/git-commit`、`/review-diff`。

**触发方式**：在 Chat 输入框的**行首**输入 `/`，输入框上方弹出候选列表，顺序为：

1. `/yorz-debug`：启动 debug 模式，尝试解决疑难问题。
2. `/yorz-spec`：基于上下文启动 spec 驱动开发。
3. 你的自定义指令（项目级在前，全局在后）。
4. 末项固定为 `+ 新增指令`。

继续输入可模糊过滤，`↑` / `↓` 选择，`Enter` 或 `Tab` 确认，`Esc` 关闭。

**管理指令**：候选列表中每条自定义指令右侧悬停会出现两个图标——铅笔「编辑」和垃圾桶「删除」（删除有二次确认）。选择末项「新增指令」即可打开新增弹窗。内置的 `/yorz-spec`、`/yorz-debug` 不可编辑或删除。

**指令字段**：

| 字段         | 说明                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| `保存位置`   | 「当前项目」或「全局」。保存后不可切换，需要改作用域时请删除后重建                |
| `名称`       | 即斜杠指令名，只允许字母、数字、下划线和连字符                                    |
| `说明`       | 仅用于候选列表中的副标题，帮助辨认；留空时显示「自定义指令」                      |
| `隐藏提示词` | 发送时自动附加给 Agent，**不会出现在输入框和聊天记录中**，是指令真正的内容        |
| `预输入内容` | 选中该指令后回填到输入框的文本，会自动带上 `/指令名` 前缀，可继续编辑后再发送     |

**存储与优先级**：全局指令写入用户级 `config.json`，项目指令写入项目的 `.yorz/config.json`。两者合并展示，**项目级排在前面且优先**：全局中与项目级同名的指令会被屏蔽。因为项目配置随仓库走，团队成员克隆后即可复用同一套指令。

**发送时发生什么**：YorZ 会在服务端解析 `/` 开头的输入——内置指令展开为对应 skill 的引导，自定义指令把隐藏提示词附加给 Agent，未匹配到的指令也会补一段说明，因此 Agent 不会再回复 `Unknown command`。聊天记录里显示的始终是你自己输入的原文。

### 7.8 新建 spec

在项目首页点击「新建 spec」（或按 `Ctrl+Shift+N`），进入新建页面。

新建时需要填写：

- `类型`：`feat` 表示新功能，`refct` 表示重构或抽取，`fix` 表示缺陷修复。
- `需求内容`：输入原始诉求、痛点、期望效果、关联模块或文档。
- `附件`：可导入附件，图片支持 Cmd/Ctrl-V 粘贴。

页面会自动记忆你填写的内容，中途切走再回来不会丢失；spec 创建成功后记忆自动清空。

点击「发送」后，Agent 会按 `yorz-spec` skill 创建 spec 文档，并自动进入 plan 阶段。文档落地后，GUI 会跳转到 spec 详情页。

### 7.9 新开项目并行

新建 spec 时可以勾选「新开项目并行」。

该模式会为新 spec 创建独立 git worktree，让本次开发在新分支和新工作目录中进行，避免影响主项目当前工作区。

适合这些场景：

- 当前主项目已有未完成改动，不希望混在一起。
- 需要同时推进多个 spec。
- 希望完成后再从列表页合入主项目。

并行项目在项目列表中独立展示，其 Chat 会话、命令运行记录都与主项目隔离，不会互相干扰。完成后可在列表页使用「合入主项目」将 worktree 改动合回主项目，合并后原 worktree 中的会话记录仍可访问。

### 7.10 追加任务

在 spec 详情页点击「追加任务」，可以给已有 spec 增加新的需求、重构或缺陷修复。

追加任务支持三种类型：

- `feat 新增/扩展需求`
- `refct 重构/重写/抽取`
- `fix 修复缺陷`

提交后，YorZ 会把追加内容写入 spec，并自动重开 plan 阶段。Agent 会重新分析新增内容，再继续拆任务和执行。

如果你在正文中选中一段内容后发起追加任务，追加记录会带上引用章节和引用文本，便于 Agent 理解上下文。

### 7.11 Debug 模式

追加 `fix` 类型任务时，可以勾选「debug 模式」；也可以在 Chat 中直接发送 `/yorz-debug` 进入。

Debug 模式会让 Agent 使用更严格的调试流程，围绕「假设 → 取证 → 验证」推进，并把过程记录到当前 spec 目录下的 `debug.md`。

适合这些场景：

- 问题复现条件复杂。
- 普通修复多次失败。
- 需要保留排查证据链。

进入 Debug 流程时，YorZ 会自动把当前项目**运行中的项目命令**（名称、命令行、进程号、日志文件路径）作为上下文附给 Agent，Agent 可以直接读取日志辅助定位；没有运行中的命令时会提示 Agent 自行启动或请用户在命令菜单中启动。详见 [7.15 项目命令](#715-项目命令)。

当当前 spec 存在 `debug.md` 时，详情页会显示 「Debug」入口，可进入 Debug 页面查看记录。

### 7.12 内容批注

在 spec 详情页选中文档中的一段内容后，会出现操作菜单。

可用操作：

- `批注`：对选中内容写下意见或补充信息。
- `解释`：让 Agent 解释选中内容。

批注会写回 spec 文档，并触发 Agent 重新处理。适合纠正方案理解、补充约束或指出某段任务描述不准确。

### 7.13 plan 决策待确认项

Agent 在 plan 阶段会补齐「现状分析」「技术实现方案」和「待确认项」。

当方案中存在必须由用户判断的信息时，Agent 会在「待确认项」中留下问题，GUI 会在 spec 详情页左侧显示待确认面板。

常见待确认项类型：

- 选择型：多个方案都可行，需要用户选择。
- 确认型：Agent 有推荐方案，但影响较大，需要用户确认或否决。
- 自由文本：需要用户补充开放信息。

你可以在待确认面板中一次性填写并发送。发送后，Agent 会读取答复、更新方案，并继续 tasks 或 execute 阶段。

### 7.14 Review 功能

在 spec 详情页点击 「Review」进入 Review 页面。

Review 页面用于查看和处理当前 spec 相关改动，其 git 操作由内置的 `yorz-git-ops` skill 约束执行。

主要功能：

- `手动选择`：手动选择要处理的文件。
- `Agent 智能判定`：让 Agent 判断本次 spec 相关的变更范围。
- `提交`：提交选中的变更。
- `暂存`：暂存选中的变更。
- `丢弃`：丢弃选中的变更。该操作不可撤销，执行前会二次确认。

建议在 spec 完成并验证后进入 Review 页面，根据当前变更决定提交、暂存或丢弃。

### 7.15 项目命令

项目命令用于在 GUI 中直接启动项目里的长驻命令，例如 `pnpm dev`、watch 模式构建或测试。命令的输出会写入日志文件，Agent 可以读取这份日志协助排查问题。

**管理命令**：在项目首页「Spec 列表」标题右侧的终端图标进入命令菜单。

- 点击底部「添加命令」，填写 `名称`（例如 `dev`）和 `命令行`（例如 `pnpm dev`）后提交。命令行以 shell 方式执行，因此可以直接写管道、`&&` 或环境变量前缀。
- 点击菜单中的某条命令即可运行，随后自动跳转到该次执行的详情页。
- 悬停命令行右侧的垃圾桶图标可以「删除命令」。菜单中没有编辑入口，需要修改时删除后重建，或直接编辑 `.yorz/config.json` 的 `commands`。

命令定义保存在项目的 `.yorz/config.json`，随 git 共享；工作目录固定为项目根目录（worktree 项目则是该 worktree）。同一条命令已在运行时再次点击不会重复启动第二个进程。

**运行中命令列表**位于项目首页 spec 卡片上方，没有运行记录时不显示。每条展示状态（`运行中` / `已退出` / `已终止` / `启动失败`）、名称、命令行和已运行时长，并提供两个操作：

- `重启`：清空旧记录与日志后重新启动。
- `终止并清空`：终止进程并删除该条执行记录与日志文件，点击后会二次确认。

点击整行进入**命令执行详情页**，可以看到退出码、运行时长、日志文件相对路径（原样展示，方便复制粘贴给 Agent），以及实时滚动的输出区域。运行中可以点「终止」结束进程，同时保留记录与日志便于事后查看。

日志位于 `.yorz/tmp/commands/<runId>.log`，索引在同目录的 `index.json`；执行记录保留 7 天，服务启动时会清理过期记录。所有命令子进程随 `yorz serve` 一同退出，不会残留孤儿进程。

### 7.16 图表查看

spec 文档中的 `mermaid` 代码块会被渲染成图表。每张图右上角有「最大化图表」按钮，点击后进入全屏查看器：

- 滚轮以鼠标位置为中心缩放，也可以用「放大」/「缩小」按钮。
- 按住拖拽可平移。
- 「重置视图」回到 1:1。
- 按 `Esc` 或「关闭图表查看器」退出。

图表按矢量重新布局，放大后文字和线条依然清晰。打开时会自动按视口大小适配。

### 7.17 系统提示与版本更新

GUI header 左侧、`YorZ` 品牌名右边会出现一个带红点的铃铛按钮，**仅在存在系统提示时显示**。点击展开「系统提示」列表。

目前的提示类型是版本更新：服务启动时会检查一次 npm 上的最新版本，之后每 12 小时检查一次。发现新版时会提示「发现新版本 —— YorZ x.y.z 已发布，当前版本 a.b.c」。

可用操作：

- `更新`：自动按你使用的包管理器（pnpm / npm / yarn / bun）执行全局安装最新版。执行期间按钮显示「更新中…」。
- `重启服务`：更新成功后按钮会变为「重启服务」，点击即可重启 YorZ Service 并自动刷新页面。注意重启会中断正在运行中的任务，恢复后可以在 Chat 中发送「继续」。
- `删除提示`：右侧的垃圾桶图标可以移除该条提示。下次检测到新版本时仍会重新出现。

提示不会持久化，`yorz serve` 重启后清空，由下一次检测重新生成。检测失败（例如网络不通）只写日志，不会打扰你。

## 8. 常见工作流

### 8.1 首次接入项目

```bash
npm install -g @yorz/cli
yorz serve
yorz add /path/to/your/project
```

然后打开 `http://localhost:7423`，在左侧选择项目。建议顺手在 header 三横菜单里确认默认 Agent 与外观偏好。

### 8.2 处理一个新需求

1. 在项目首页点击「新建 spec」（或按 `Ctrl+Shift+N`）。
2. 选择 `feat`，填写需求内容。
3. 点击「发送」，等待 Agent 创建 spec 并进入 plan。
4. 如有待确认项，在面板中答复并发送。
5. Agent 继续拆任务和执行。
6. 完成后进入 「Review」页面处理变更。

### 8.3 用 Chat 快速处理零散任务

1. 在 Chat 面板点 `+` 新建会话。
2. 直接描述任务，`@` 引用相关文件，必要时粘贴截图。
3. 觉得任务规模超出预期时，发送 `/yorz-spec` 让 Agent 基于当前上下文转入 spec 驱动流程。
4. 遇到疑难问题时，发送 `/yorz-debug` 进入 Debug 流程。

### 8.4 并行处理多个需求

1. 新建 spec 时勾选「新开项目并行」。
2. 在新 worktree 项目中让 Agent 推进任务。
3. 主项目可以继续处理其它工作。
4. 完成后在列表页使用「合入主项目」。

### 8.5 追加缺陷并进入 Debug

1. 如果复现需要跑服务，先在命令菜单启动对应命令（例如 `dev`）。
2. 在 spec 详情页点击「追加任务」。
3. 选择 `fix 修复缺陷`。
4. 勾选「debug 模式」。
5. 填写缺陷复现、现象、期望结果。
6. 点击「发送」，Agent 会自动拿到运行中命令的日志路径并进入 Debug 流程。
7. 在 「Debug」页面查看 `debug.md` 记录。

### 8.6 沉淀一条自定义斜杠指令

1. 在 Chat 输入框行首输入 `/`，选择列表末项「新增指令」。
2. 选择保存位置：只给自己用选「全局」，想让团队共享选「当前项目」。
3. 填写名称（如 `git-commit`）与说明。
4. 在「隐藏提示词」里写下完整的提示词，例如「使用 git 提交当前会话相关的变更文件，并按仓库约定撰写 commit message」。
5. 需要每次补充信息时，在「预输入内容」里写好模板，选中指令后可继续编辑再发送。
6. 保存后即可用 `/git-commit` 调用。
