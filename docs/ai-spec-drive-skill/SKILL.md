# Spec Drive Skill

将单个 spec 文档作为状态机执行，围绕 `plan`、`tasks`、`execute` 三阶段推进，并把状态持续写回文档。

## 输入约定

- `spec_path`：必填，目标 spec 文档路径。
- `mode`：可选，`plan|tasks|execute|auto`，默认 `auto`。
- 批注前缀：`！！！`。

## 全局硬约束

- 仅更新目标 `spec_path` 文档，不修改无关文档。
- 每次写回文档都必须更新 `## 流程状态`，至少包含：
  - `当前阶段`
  - `最近动作`
  - `更新时间`（`YYYY-MM-DD`）
- 若以下章节不存在，先补齐再继续：
  - `## 流程状态`
  - `## 现状分析`
  - `## 技术实现方案`
  - `## 待确认问题`
  - `## 任务清单`
  - `## 执行记录`
- 若在已有 spec 中识别到“新增/扩展需求”或“新增 bug”（无论来自正文变更或 `！！！` 批注），必须将 `当前阶段` 立即切回 `plan`，并在 `最近动作` 记录“变更重开流程”。
- 变更重开后，必须仅针对新增内容重新走完 `plan -> tasks -> execute`：先补充分析与确认，再拆任务并执行；未受影响的既有结论/任务可保留，但受影响任务必须重新评估与改写。

## 自动模式判定顺序（严格按顺序）

1. 若识别到新增/扩展需求或新增 bug，进入 `plan`（重开流程）。
2. 否则，若文档存在任意 `！！！` 批注，进入 `tasks`。
3. 否则，若 `## 待确认问题` 下存在有效条目（非 `- 暂无`），停止推进并等待人工批注。
4. 否则，若存在未完成任务（`- [ ]`），进入 `execute`。
5. 否则，若 `## 技术实现方案` 为空或明显不完整，进入 `plan`。
6. 否则，进入 `tasks` 生成或刷新详细任务清单。

## 阶段行为

### 阶段一：plan

理解文档，分析现有代码，编写技术实现方案，更新到当前文档中；
需要确认的问题以列表格式写入文档，待用户后续会进行审阅批注；
暂时只需更新文档，不要实施代码

- 目标：输出 `现状分析`、`技术实现方案`、`待确认问题`。
- 禁止：输出任务清单格式 `- [ ]`。
- 若误生成 `- [ ]`，写回前必须改为无序列表 `- ` 或移除。
- `待确认问题` 必须使用无序列表；无问题时写 `- 暂无`。

### 阶段二：tasks

根据批注内容（！！！前缀）更新文档中的技术方案；
审查批注内容是否正确解答了`待确认问题`，是否会与目标或技术方案产生新的冲突或歧义；
若批注或正文改动引入了新增/扩展需求或新增 bug，则必须先切回 `plan`，补充 `现状分析`/`技术实现方案`/`待确认问题` 后再继续；
如果存在冲突或歧义，则回退到 `plan` 阶段，更新到文档 `待确认问题` 中，退出执行，等待重新批注；
否则将技术方案，拆解为详细的可执行任务（格式：`- [ ] 任务x`），写入文档；
然后进入 `execute`。

- 输入：读取并消费所有 `！！！` 批注。
- 批注消费规则：
  - 将批注意图合并进 `技术实现方案` 与 `任务清单`。
  - 处理完成后删除对应 `！！！` 文本。
- 产出任务清单要求：
  - 仅使用 `- [ ]`。
  - 每项任务包含“动作 + 对象 + 验收点”。
  - 禁止泛化任务（如“完善功能”“优化逻辑”）。
- 自动衔接：若 `待确认问题` 为 `- 暂无`（或为空），在同一轮继续进入 `execute`。

### 阶段三：execute

理解文档内容，然后执行文档中的任务，每完成一个任务后勾选文档中的任务状态

- 顺序执行 `任务清单` 中未完成项。
- 执行中若发现新增/扩展需求或新增 bug，立即停止继续勾选，切回 `plan` 并记录重开原因。
- 每完成一项后立刻：
  - 将该项从 `- [ ]` 改为 `- [x]`。
  - 在 `执行记录` 增加一条结果（改动点、验证方式、阻塞项若有）。
- 默认执行验证：
  - 若仓库存在可用测试/构建命令，默认执行并记录结果。
  - 若当前环境无法执行验证，记录原因并保留相关任务未完成或追加阻塞记录。

## 待确认问题判定

- 仅解析 `## 待确认问题` 章节。
- 视为“未决”的条目：`- ` 开头且内容不是 `暂无`。
- 当存在未决条目时，禁止自动进入 `execute`。

## 输出优先级

1. 先保证状态正确（章节齐全、流程状态更新）。
2. 再保证结构正确（列表格式、任务格式）。
3. 最后保证内容质量（可执行、可验收、可追踪）。
