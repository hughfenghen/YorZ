# Mermaid 图表输出指南

本模块指导 Agent 在 spec 文档的各个阶段（plan / tasks / execute）按需输出 mermaid 图表，对信息进行"升维"，提升可读性与决策效率。

## 图表选型表

根据信息特征选择最合适的图表类型。**优先选择最能清晰传达信息的类型**，而非最复杂的类型。

| 信息特征                       | 推荐图表            | 典型 spec 落点             |
| ------------------------------ | ------------------- | -------------------------- |
| 流程、步骤、决策分支           | **flowchart**       | 技术方案、执行流程         |
| 组件间交互、消息传递、API 调用 | **sequenceDiagram** | 现状分析链路、技术方案交互 |
| 状态机、阶段流转、生命周期     | **stateDiagram**    | spec 阶段流转、任务状态机  |
| 类结构、继承关系、接口         | **classDiagram**    | 数据模型、模块结构         |
| 数据库表、实体关系             | **erDiagram**       | 数据模型设计               |
| 系统架构、组件依赖、分组       | **architecture**    | 现状分析架构、总体架构     |
| 层级关系、知识结构、脑暴       | **mindmap**         | 需求拆解、影响面分析       |
| 项目计划、时间线、里程碑       | **gantt**           | 任务排期                   |
| 占比、分布                     | **pie**             | 数据分布分析               |
| 历史事件、时间轴               | **timeline**        | 执行记录、变更历史         |

> 完整图表类型列表与语法参考见 `references/` 目录（flowchart.md / sequenceDiagram.md / stateDiagram.md / classDiagram.md / entityRelationshipDiagram.md / architecture.md / mindmap.md / gantt.md 等 38 个文件）。

## 各阶段落点指导

### plan 阶段

- **## 现状分析**：用 **architecture** 图描述现有系统结构与组件依赖；用 **flowchart** 描述当前业务流程或数据流。
- **## 技术实现方案**：用 **flowchart** 描述方案逻辑与决策分支；用 **sequenceDiagram** 描述模块间交互与时序；用 **architecture** 图描述改造后的总体架构。

### tasks 阶段

- **## 任务清单**：当任务间存在依赖关系时，可用 **flowchart** 绘制任务依赖图辅助理解执行顺序。

### execute 阶段

- **## 执行记录**：可用 **flowchart** 或 **sequenceDiagram** 描述已完成变更的影响范围与数据流变化。

## 输出规范

1. **代码块包裹**：mermaid 代码必须用 ` ```mermaid ` 代码块包裹。
2. **语法正确**：确保代码可直接渲染，无语法错误。不确定时参考 `references/` 对应文档。
3. **语义化命名**：节点、变量使用有意义的名称（如 `Skill输出` 而非 `A`），便于理解。
4. **适度样式**：需要时包含样式（颜色、形状区分）以提升可读性，但不要过度装饰。
5. **中文友好**：节点文本可使用中文；ID 使用英文或拼音以避免 mermaid 解析问题。

### 示例

```mermaid
flowchart LR
    A[Skill 输出 mermaid code] --> B[spec.md]
    B -->|SSE 推送| C[GUI SpecDetail]
    C --> D[fence rule 识别]
    D --> E[异步渲染图形]
```

## 节制原则

- **只在信息确实复杂、图形能显著提升可读性时输出**，避免为出图而出图。
- 简单的线性列表、两三步操作无需图表。
- 单个章节不宜超过 2 张图，过多图表反而降低可读性。
- 图表应**补充**文字描述而非替代——文字说明图表无法表达的细节。
- 如果不确定是否需要图表，优先不画，在文字分析足够清晰时省略。
