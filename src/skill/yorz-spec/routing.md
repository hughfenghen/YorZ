# 自动模式判定顺序（严格按顺序）

本规则用于在 `mode=auto` 时确定本轮进入哪个阶段。**严格按顺序**判定，命中即停，不要跳过。

1. 若 `spec_path` 缺省：先按 [输入约定](./conventions.md#输入约定) 从 session 上下文恢复 spec 路径；恢复成功则把该路径作为 `spec_path` 进入后续判定；恢复失败才进入 [新建 spec 流程](./new-spec.md) 并以 `plan` 起步。
2. 否则，**优先扫描 `## 追加任务` 中是否存在 `[open]` 条目**：存在即视为"新增/扩展需求"或"新增 bug"信号，按下一条判定进入 `plan`（重开流程，见 [全局硬约束](./rewrite-rules.md)）。
3. 否则，若识别到新增/扩展需求或新增 bug，进入 `plan`（重开流程）。
4. 否则，若文档存在任意 `！！！` 批注，进入 [tasks](./tasks.md)。
5. 否则，若 `## 待确认问题` 下存在有效条目（非空态 `_暂无_`），停止推进并等待人工批注。
6. 否则，若存在未完成任务（`- [ ]`），进入 [execute](./execute.md)。
7. 否则，若 `## 技术实现方案` 为空或明显不完整，进入 [plan](./plan.md)。
8. 否则，进入 [tasks](./tasks.md) 生成或刷新详细任务清单。

## 待确认问题判定

- 仅解析 `## 待确认问题` 章节。
- 视为"未决"的条目：章节内存在任一 `### ` 三级标题子标题（无论其正文是否以 `（自由文本）` 结尾）。
- 空态判定：章节内仅有 `_暂无_` 斜体段落（或整章为空）即视为无未决条目。
- 当存在未决条目时，禁止自动进入 `execute`。
