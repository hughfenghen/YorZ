# 阶段一：plan

理解文档，分析现有代码，编写技术实现方案，更新到当前文档中；需要确认的问题以三级标题 + 有序列表候选的结构写入文档，待用户后续会进行审阅批注；暂时只需更新文档，不要实施代码。

> 在输出 `## 现状分析` 与 `## 技术实现方案` 时，按需嵌入 mermaid 图表提升可读性——参见 [mermaid 图表输出指南](./mermaid.md)。

## 目标

- 输出 `## 现状分析`、`## 技术实现方案`、`## 待确认问题` 三节。
- `待确认问题` 每条问题必须使用三级标题 `### N.M 问题正文`；无问题时整章仅保留 `_暂无_` 一行（斜体段落，非列表项）。
- 禁止：输出任务清单格式 `- [ ]`，若误生成 `- [ ]`，写回前必须改为对应结构或移除。
- 若 `## 追加任务` 存在 `- [open] [feat|refct|fix] ...` 条目，必须将其纳入 `## 现状分析` / `## 技术实现方案` / `## 待确认问题` 的分析范围；按类型差异化处理：
  - `[feat]`：重在范围拆解（新增能力的边界、用户故事、影响章节）。
  - `[refct]`：重在影响面与回归（被重构模块的依赖图、潜在破坏点、保留行为的回归手段）。
  - `[fix]`：重在根因与最小修复（复现路径、根因定位、最小代码改动半径）。
- plan 阶段**不修改** `## 追加任务` 中条目的状态标记，仅消费其内容。

## 候选项硬约束

每条问题**若**给出候选项，则必须**恰好** 1 个候选项以 ` （推荐）` 结尾；候选数量不做强制下限。无法或不必枚举（如概念澄清、错别字确认、开放性补全）时，在问题正文末尾追加 `（自由文本）` 后缀，显式声明该条退化为自由文本条目。

## 待确认问题结构

`## 待确认问题` 章节中，每条问题写作三级标题 `### N.M 问题正文`；候选答案紧随其后，以**一级有序列表** `1. 候选文本` / `2. 候选文本` … 排布，并在恰好 1 个候选项尾部追加 ` (推荐)`（或全角 ` （推荐）`）：

```
### 5.1 候选答案的展现形式应采用哪种？
1. 嵌套子列表
2. 表格 (推荐)
3. 自定义 YAML 块
```

对于无法/不必枚举候选答案的问题（澄清、确认错别字、开放补全等），不要硬凑候选项，而是在三级标题正文末尾追加 `（自由文本）` 后缀显式声明退化，其下不再跟有序列表：

```
### 5.2 release notes 文案应该怎么写？（自由文本）
```

空态：整章仅保留 `_暂无_` 一行（斜体段落），不写为列表项，如：

```
## 5. 待确认问题

_暂无_
```

- 候选项采用单选语义：不引入"多选"概念；**给出候选项的问题必须恰 1 个 `（推荐）` 标记**，0 个或 ≥ 2 个均视为 Agent 输出违规，必须自检修正。
- 候选项 label 不限字符长度，GUI 端以 CSS 自适应换行处理。
- 推荐项必须放在候选项中已有的某个选项尾部，不要新增"以推荐项为名"的额外条目。
- 问题正文末尾的 `（自由文本）` 后缀是 GUI 强制 freeform 渲染的显式信号；不带后缀且无有序列表候选时亦按 freeform 渲染，但建议补齐后缀以显式声明。
- 三级标题编号（`### N.M`）由 [conventions.md](./conventions.md) 的自动重排逻辑维护：Agent 写回前按 body 出现顺序刷编号；parser 端会自动剥离编号，只保留问题正文。
- 若需要保留"已确认决策快照"等辅助信息，应放到独立二级章节（如 `## 已确认决策`）；不允许在 `## 待确认问题` 章节内嵌 `### 已确认决策快照` 之类的子节，parser 会把 `### ` 视作新问题起点。
- 用户在 GUI 中提交答复时，结果会作为一个 `## 用户批注` 段落追加到 spec 末尾，每条答复一段 `> 引用 + ！！！备注` 块；该章节的清理时机见 [tasks 阶段](./tasks.md)。

## 产出前自检（以 lint 报告为准）

写回 spec.md 后，运行 `yorz lint <spec_path> --format json` 并把每条 `severity: error` 修到干净——具体判据以 lint 输出为唯一真相。以下 ruleId 索引供 Agent 按报告快速定位违规场景：

| ruleId                                                                                  | 覆盖场景（简述）                                                                                                                                    |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pending-questions/structure`                                                           | 每条 `### ` 问题要么有 `1. / 2. / …` 有序候选 + 恰 1 个 `(推荐)`；要么以 `（自由文本）` 结尾。无序 `- `、缺推荐、多推荐、遗漏自由文本后缀均被捕获。 |
| `pending-questions/empty`                                                               | 空态整章必须是 `_暂无_` 斜体段落，不允许 `- 暂无` 列表项或空章节。                                                                                  |
| `pending-questions/no-named-recommend`                                                  | 候选项中禁止 `推荐：<name>` 独立条目——推荐项必须以 `(推荐)` / `（推荐）` 后缀形式附着于已有候选。                                                   |
| `heading/h1-single`                                                                     | body 中一级标题 `# ` 恰 1 个，位于所有 `## ` 之前。                                                                                                 |
| `heading/section-level`                                                                 | 七大必备章节及可选章节 `追加任务` 必须以 `## ` 出现，禁止写成 `# `。                                                                                |
| `heading/numbering`                                                                     | `## N. ` / `### N.M ` 按 body 顺序连续、不跳号。                                                                                                    |
| `sections/required`                                                                     | 七大必备章节齐全（`追加任务` 为可选章节，由用户触发追加时懒插入），若可选章节存在则位置固定在 `任务清单` 与 `执行记录` 之间。                       |
| `frontmatter/required-fields` / `frontmatter/updated-at` / `frontmatter/summary-length` | 4 字段齐全 + 顺序固定；`updated_at` 秒级并带单引号；`summary` 非空 ≤ 200。                                                                          |
| `task-list/format` / `append-task/format`                                               | 任务清单单层 `- [ ] / - [x]`；追加任务 `- [open\|fixed] [feat\|refct\|fix] ...`（或 `- 暂无`）。                                                    |
| `mermaid/fence` / `mermaid/syntax`                                                      | mermaid 代码块首行 diagram type 白名单；`mermaid.parse` 深校验兜底。                                                                                |
| `annotations/leftover`                                                                  | 正文残留 `！！！` 批注（tasks 阶段应消费后删除）。                                                                                                  |
