# 最近访问入口

## 1. 背景

用户反馈每次打开应用都要在 spec 列表里翻找昨天碰过的几个 spec。希望首屏看到一个「最近访问」入口直接跳转。

## 2. 需求

- 新增「最近访问」入口，列出用户近期访问过的 spec
- 需要决定：入口挂在导航哪一层？数据来自本地还是服务端？最多保留多少条？是否提供清空按钮？

## 3. 现状分析

当前 GUI 主导航只有两个 tab：`Specs`、`Settings`。没有任何位置承载「最近访问」类的快捷入口。Spec 列表本身按 mtime 排序，并不区分「访问过 / 未访问过」，也没有任何客户端访问记录。

具体分析：

- **导航层**：主导航仅 `Specs`、`Settings` 两个 tab，首屏直接展示 spec 全量列表，无快捷入口区块。
- **数据层**：spec 列表来源于后端 `spec-store`，按文件 mtime 排序返回；前端无独立的访问记录存储（localStorage / IndexedDB 均未使用）。
- **交互层**：用户打开 spec 详情时不会产生任何"已访问"标记，刷新页面后无法快速回到上次查看的 spec。
- **结论**：需要同时新增「数据记录机制」和「UI 展示入口」，且二者均需确认实现方式后才能拆解任务。

## 4. 技术实现方案

整体思路：在用户访问 spec 详情时记录访问行为，在首屏展示最近访问列表，提供快速跳转。

### 4.1 数据记录

- 在 spec 详情页加载时触发访问记录写入。
- 存储结构：`{ specId, lastAccessedAt }` 列表，按 `lastAccessedAt` 降序。
- 去重策略：同一 spec 多次访问只保留最新一条。

### 4.2 UI 展示

- 在首屏（Spec 列表页）顶部新增「最近访问」区块，与全量列表分区展示。
- 每条记录以卡片或行形式展示 spec 标题 + 最后访问时间，点击跳转到详情页。
- 当记录为空时隐藏整个区块。

### 4.3 清空策略

- 提供「清空」按钮，一键清除全部最近访问记录。

> 以下关键决策点需用户确认后才能进一步细化，详见「待确认问题」。

## 5. 待确认问题

- 入口挂在导航哪一层？
  - 首页顶部独立区块，不新增 tab （推荐）
  - 主导航新增第三个 tab「最近访问」
  - 侧边栏常驻列表
- 数据来自本地还是服务端？
  - 纯客户端 localStorage 记录，无需后端改动 （推荐）
  - 服务端 spec-store 新增访问日志接口
  - 混合模式：客户端记录 + 服务端同步
- 最多保留多少条最近访问记录？
  - 10 条 （推荐）
  - 5 条
  - 20 条
- 是否提供「清空最近访问」按钮？
  - 提供，放在区块标题右侧 （推荐）
  - 不提供，仅依靠上限自动淘汰
